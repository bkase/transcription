## XcodeGen with SPM packages
- When using XcodeGen with SPM dependencies, specify `product:` alongside `package:`
- Product names differ from package names (e.g., swift-composable-architecture -> ComposableArchitecture)
- Framework targets need PRODUCT_NAME and PRODUCT_MODULE_NAME settings to avoid empty module names
- SPM dependencies need to be resolved before building: `xcodebuild -resolvePackageDependencies`

## Swift Testing module scope

## Point-Free swift-dependencies
- `@DependencyClient` macro generates struct-based dependency interfaces
- Non-throwing closures need explicit default values: `= { false }`
- Throwing closures get auto-generated "unimplemented" stubs that fail tests
- Add `DependenciesMacros` product for the `@DependencyClient` macro
- `testValue = Self()` creates unimplemented stubs - tests must override for noop behavior
- Register with `DependencyKey` protocol for `liveValue`, `testValue`, `previewValue`
- Extend `DependencyValues` to add `@Dependency(\.myClient)` accessor

- SPM packages in XcodeGen don't auto-resolve transitive dependencies for linking

- TCA features need explicit CasePaths dependency for @Reducer macro-generated code
- DependenciesMacros needed for any target using @DependencyClient macro
- Set GENERATE_INFOPLIST_FILE: true and ALWAYS_SEARCH_USER_PATHS: false in base settings
- Use SWIFT_EXPLICIT_MODULES: false and ONLY_ACTIVE_ARCH: true to avoid parallel build issues

## GRDB.swift for SQLite persistence
- Use GRDB package from `https://github.com/groue/GRDB.swift` (not a Point-Free package)
- Records implement `FetchableRecord`, `PersistableRecord`, `Codable`, `Sendable`
- `DatabaseMigrator` handles schema migrations; registered migrations are idempotent
- `DatabaseQueue` is the main entry point; use `.inMemory` for tests
- Swift `Date` requires `import Foundation` (not auto-imported with GRDB)
- `DatabaseClient.live(dbQueue:)` factory creates a live client instance from a DatabaseQueue
- Use `dbQueue.read { db in }` for queries and `dbQueue.write { db in }` for mutations (async-safe)
- GRDB `order(Column("x"))` for sorting, `filter(Column("x") == y)` for filtering
- Foreign key cascades work automatically when defined in migrations (ON DELETE CASCADE)

## SQLite FTS5 full-text search
- FTS5 virtual tables: `CREATE VIRTUAL TABLE x USING fts5(col1, col2 UNINDEXED, ...)`
- UNINDEXED columns stored but not searchable (useful for foreign keys like sessionId)
- Use triggers (AFTER INSERT/UPDATE/DELETE) to keep FTS in sync with source table
- Can't use external content table when column names differ (use regular FTS table + triggers)
- bm25() function only works directly in FTS queries, not with GROUP BY aggregates
- Alternative: count matches per session with `COUNT(*) ... GROUP BY sessionId ORDER BY matchCount DESC`
- FTS5 MATCH syntax: `WHERE table MATCH 'query'`

## FluidAudio SDK integration
- FluidAudio package is at https://github.com/FluidInference/FluidAudio (v0.10.0, not 1.x yet)
- AsrModels.downloadAndLoad(version: .v3) downloads and initializes ASR models

- Audio input must be 16kHz mono Float samples
- Models are downloaded to ~/Library/Application Support/FluidAudio/Models/
- Lazy initialization pattern: ensureInitialized() method in actor to initialize on first use
