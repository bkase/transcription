## XcodeGen with SPM packages
- When using XcodeGen with SPM dependencies, specify `product:` alongside `package:`
- Product names differ from package names (e.g., swift-composable-architecture -> ComposableArchitecture)
- Framework targets need PRODUCT_NAME and PRODUCT_MODULE_NAME settings to avoid empty module names
- SPM dependencies need to be resolved before building: `xcodebuild -resolvePackageDependencies`

## Swift Testing
- Swift Testing with `@Test` works out of the box with `swift test`
- Simpler than XCUITest for repo structure validation tests
- Root Package.swift can define test targets that run via SPM

## Pre-commit hooks
- Git hooks live in `.git/hooks/` (not tracked in git)
- Must be executable (`chmod +x`)
- Exit code determines if commit proceeds

## Beads workflow
- `br ready --json` shows actionable issues
- `br update <id> --status=in_progress` to claim
- `br close <id> --reason="..."` when done
- `br sync --flush-only` exports to JSONL

## Package.resolved with XcodeGen
- Store Package.resolved outside the generated .xcodeproj (e.g., xcodegen/Package.resolved)
- Copy it into the generated project after xcodegen runs
- The generated .xcodeproj is gitignored so internal Package.resolved isn't tracked

## Swift Testing module scope
- Private/internal helper functions in same module are visible across test files
- Avoid defining same helper function in multiple test files (redeclaration error)
- Create a shared TestHelpers.swift for common utilities

## Point-Free swift-dependencies
- `@DependencyClient` macro generates struct-based dependency interfaces
- Non-throwing closures need explicit default values: `= { false }`
- Throwing closures get auto-generated "unimplemented" stubs that fail tests
- Add `DependenciesMacros` product for the `@DependencyClient` macro
- `testValue = Self()` creates unimplemented stubs - tests must override for noop behavior
- Register with `DependencyKey` protocol for `liveValue`, `testValue`, `previewValue`
- Extend `DependencyValues` to add `@Dependency(\.myClient)` accessor

## XcodeGen transitive dependencies
- SPM packages in XcodeGen don't auto-resolve transitive dependencies for linking
- If target A depends on Models and Models depends on Tagged, target A needs explicit Tagged dependency
- TCA features need explicit CasePaths dependency for @Reducer macro-generated code
- DependenciesMacros needed for any target using @DependencyClient macro
- Set GENERATE_INFOPLIST_FILE: true and ALWAYS_SEARCH_USER_PATHS: false in base settings
- Use SWIFT_EXPLICIT_MODULES: false and ONLY_ACTIVE_ARCH: true to avoid parallel build issues

## TCA TestStore
- TCA's TestStore requires @MainActor on test structs
- Use Swift Testing with `@Test` for TCA tests in iOS targets
- TestStore tests run via xcodebuild (not swift test for iOS targets)
- Makefile test target should include `-only-testing:TestTargetName` for xcode tests

## Swift regex literals
- Regex literals `/pattern/` can conflict with Swift's macro/number parsing
- Use `#[0-9A-Fa-f]` inside regex causes compile errors (looks like integer literal)
- Prefer helper functions with `allSatisfy` for simple validation instead of regex

## SPM package tests in monorepo
- Root Package.swift `swift test` doesn't run tests from local package dependencies
- Add separate test commands to Makefile: `cd Packages/Core/Models && swift test`
- Each local SPM package has its own test target that must be run independently

## GRDB.swift for SQLite persistence
- Use GRDB package from `https://github.com/groue/GRDB.swift` (not a Point-Free package)
- Records implement `FetchableRecord`, `PersistableRecord`, `Codable`, `Sendable`
- `DatabaseMigrator` handles schema migrations; registered migrations are idempotent
- `DatabaseQueue` is the main entry point; use `.inMemory` for tests
- Swift `Date` requires `import Foundation` (not auto-imported with GRDB)
- `DatabaseClient.live(dbQueue:)` factory creates a live client instance from a DatabaseQueue
- Use `dbQueue.read { db in }` for queries and `dbQueue.write { db in }` for mutations (async-safe)
- GRDB `order(Column("x"))` for sorting, `filter(Column("x") == y)` for filtering
- Foreign key cascades work automatically when defined in migrations (ON DELETE CASCADE)

## SnapshotTesting with Swift Testing
- swift-snapshot-testing works with Swift Testing `@Test` macro (not just XCTest)
- Use `withSnapshotTesting(record: .all)` or `.missing` to control record mode
- Environment variable `SNAPSHOT_RECORD=1` can control record mode externally
- `SwiftUISnapshotLayout.device(config: .iPhone13Pro)` for consistent device sizing
- Separate test target for snapshots keeps concerns isolated

## AVAudioEngine mocking for tests
- Create protocols (AudioEngineProtocol, AudioInputNodeProtocol) to abstract AVFoundation classes
- Use `@retroactive @unchecked Sendable` conformance for AVFoundation types
- Property name conflicts in extensions can cause infinite recursion (e.g., `inputNode` → use `audioInputNode`)
- AsyncStream.makeStream(bufferingPolicy: .unbounded) for immediate continuation access
- Keep stream references alive in tests - dropped streams may trigger termination handlers
- Sync tests work with `throws`, async tests with `async throws` - closures on @DependencyClient are async

## Audio file writing with ExtAudioFile
- Use ExtAudioFile API (not AVAudioFile) for lower-level control over audio file writing
- AudioStreamBasicDescription requires kAudioFormatFlagIsFloat | kAudioFormatFlagIsPacked for Float32 PCM
- ExtAudioFileCreateWithURL needs file type ID: kAudioFileCAFType or kAudioFileWAVEType based on extension
- ExtAudioFileRef needs wrapper class for actor isolation (class ExtendedAudioFile: @unchecked Sendable)
- Use actors for thread-safe audio file writing state management
- For mock dependency clients in tests with Sendable closures, use actors to avoid Swift 6 warnings
- Linear interpolation resampling: outputIndex * inputRate/outputRate gives source sample position

## Mock client patterns with actors
- Use actors for mock client state to ensure thread-safe access
- Capture local copies of script data before async operations to avoid actor hop warnings
- Use `[weak self]` in Task closures with actor isolation to avoid memory leaks
- Complex `.map { }` expressions with many initializer parameters can cause compiler timeout
- Prefer explicit `for` loops over `.map` when creating many objects with complex initializers

## Root Package.swift test targets

## SQLite FTS5 full-text search
- FTS5 virtual tables: `CREATE VIRTUAL TABLE x USING fts5(col1, col2 UNINDEXED, ...)`
- UNINDEXED columns stored but not searchable (useful for foreign keys like sessionId)
- Use triggers (AFTER INSERT/UPDATE/DELETE) to keep FTS in sync with source table
- Can't use external content table when column names differ (use regular FTS table + triggers)
- bm25() function only works directly in FTS queries, not with GROUP BY aggregates
- Alternative: count matches per session with `COUNT(*) ... GROUP BY sessionId ORDER BY matchCount DESC`
- FTS5 MATCH syntax: `WHERE table MATCH 'query'`

## Actors for deterministic test audio generation
- Use actors (not classes with NSLock) for thread-safe async state management
- NSLock is unavailable from async contexts in Swift 6 - avoid lock/unlock in async methods
- Actor properties can be read directly within actor-isolated methods without locks
- `[weak self]` in Task closures with actors prevents retain cycles
- AsyncStream.makeStream() for immediate continuation access within actors

## Package version constraints with TCA + swift-perception
- TCA macros require swift-syntax 602.0.0+ for `GenericArgumentSyntax.Argument`
- swift-perception versions < 2.0 constrain swift-syntax to < 602.0.0, causing build failures
- Update project.yml `from:` constraints to require compatible versions (e.g., swift-perception from "2.0.0")
- Clean DerivedData/SourcePackages when changing version constraints to avoid stale artifacts
- Keep Package.resolved in sync with actually resolved versions for reproducible builds

## FluidAudio SDK integration
- FluidAudio package is at https://github.com/FluidInference/FluidAudio (v0.10.0, not 1.x yet)
- AsrModels.downloadAndLoad(version: .v3) downloads and initializes ASR models
- DiarizerModels.downloadIfNeeded() downloads diarization models if not cached
- DiarizerManager.initialize(models:) takes consuming parameter (must be passed directly)
- ASRConfig.default and DiarizerConfig.default for default ML configurations
- AsrManager.transcribe([Float], source: .microphone) for transcription
- DiarizerManager.performCompleteDiarization([Float], sampleRate:, atTime:) for speaker diarization
- DiarizationResult.segments contains TimedSpeakerSegment with speakerId, startTimeSeconds, endTimeSeconds
- Audio input must be 16kHz mono Float samples
- Models are downloaded to ~/Library/Application Support/FluidAudio/Models/
- Lazy initialization pattern: ensureInitialized() method in actor to initialize on first use

## Testing FluidAudio integration logic
- Extract testable utilities to separate files (e.g., DiarizationMapping.swift) to avoid FluidAudio SDK dependency in tests
- Create plain Swift structs (SpeakerSegment) that mirror FluidAudio types for testing
- Dominant speaker = speaker with longest total duration across all segments in a chunk
- Display orders assigned in discovery order (first speaker seen = 1, second = 2, etc.)
- Use `max(0, endTime - startTime)` to clamp negative durations to zero
